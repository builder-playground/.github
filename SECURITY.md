# Security Policy / 安全策略

## Reporting a vulnerability / 上报安全问题

Please do not open a public issue for a security problem. Use GitHub's private reporting instead:

请不要为安全问题开公开 issue，请改用 GitHub 的私密上报：

1. Go to the **Security** tab of the affected repository. / 打开出问题仓库的 **Security** 标签页。
2. Click **Report a vulnerability**. / 点击 **Report a vulnerability**。
3. Describe the issue, the impact, and how to reproduce it. / 说明问题、影响与复现方式。

If private reporting is not enabled for that repository, open an issue asking a maintainer for a private channel, and do not include the details in the issue itself.

如果该仓库尚未开启私密上报，请开 issue 请维护者提供私密渠道，但不要在 issue 里写漏洞细节。

## What to expect / 我们会怎么做

- We aim to acknowledge a report within a few days. / 我们会在几天内确认收到。
- We will tell you whether we accept the issue and roughly what the fix looks like. / 会告知是否确认以及修复思路。
- Please give us reasonable time to ship a fix before disclosing publicly. / 公开披露前请给我们合理的修复时间。

## Scope / 范围

This policy covers repositories in the `builder-playground` organization. Third-party dependencies should be reported to their own maintainers.

本策略覆盖 `builder-playground` 组织下的仓库；第三方依赖的问题请报给其上游维护者。

## Please do not include / 请不要包含

Tokens, keys, credentials, personal data, or internal links in public issues or pull requests.

在公开 issue 或 PR 中不要包含 token、密钥、凭证、个人信息或内部链接。
